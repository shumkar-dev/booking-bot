# Бот записи клиентов

Telegram-бот для салонов, барбершопов и студий: клиент записывается в несколько
нажатий, администратор подтверждает заявку в своём чате, бот сам напоминает
клиенту за 24 часа и за 2 часа до визита.

## Возможности

- Запись: услуга → день → время → контакты → подтверждение
- Проверка занятости слотов, двойная запись на одно время невозможна
- Постоянные клиенты записываются без повторного ввода контактов
- Карточка заявки администратору с кнопками «Принять / Отклонить / Перезвонить / Написать»
- Двусторонний чат клиент ↔ администратор
- Автонапоминания за 24 ч и 2 ч
- Информационные разделы: цены, адрес, Instagram

## Архитектура

```
bot.py            точка входа: сборка Bot/Dispatcher, graceful shutdown
config.py         конфигурация из окружения, услуги, график работы
scheduling.py     генерация дней и слотов, валидация времени
database.py       слой доступа к данным (aiosqlite)
keyboards.py      инлайн-клавиатуры
states.py         FSM-состояния
utils.py          валидация ввода, экранирование, безопасная отправка
middlewares.py    антифлуд
reminders.py      фоновый цикл напоминаний
handlers/
  client.py       клиентские сценарии
  admin.py        администраторские сценарии
tests/            тесты валидации и расписания
```

Слоты не заданы константами, а вычисляются из графика работы
(`WORK_START_HOUR`, `WORK_END_HOUR`, `SLOT_STEP_MINUTES`). Благодаря этому
время визита хранится полным `datetime` с таймзоной, и напоминания считаются
от него напрямую.

## Технические решения

- **Двойная запись** блокируется частичным `UNIQUE INDEX` по `visit_at` для активных статусов. Проверка в коде — только для понятного сообщения, гонку останавливает база.
- **Права администратора** — фильтром роутера, а не проверкой в каждом хендлере.
- **Пользовательский ввод** экранируется перед вставкой в HTML-сообщения.
- **Часовой пояс** задаётся явно через `TIMEZONE`: на VPS системное время обычно UTC.
- **FSM в памяти** — состояние теряется при рестарте. При росте нагрузки заменяется на `RedisStorage` без правки хендлеров.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполнить BOT_TOKEN и ADMIN_ID
python bot.py
```

Токен получить у [@BotFather](https://t.me/BotFather), свой Telegram ID — у
[@userinfobot](https://t.me/userinfobot).

Файл `.env` в репозиторий не попадает (см. `.gitignore`). Если токен когда-либо
оказывался в коде — отзови его через `/revoke` у BotFather: удаление файла не
чистит историю коммитов.

## Настройка под другой бизнес

Услуги — словарь `SERVICES` в `config.py`. График работы, шаг слотов и
горизонт записи — через `.env`.

## Деплой (systemd)

`/etc/systemd/system/booking-bot.service`:

```ini
[Unit]
Description=Booking bot
After=network.target

[Service]
Type=simple
User=bot
WorkingDirectory=/opt/booking-bot
EnvironmentFile=/opt/booking-bot/.env
ExecStart=/opt/booking-bot/.venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now booking-bot
sudo journalctl -u booking-bot -f
```

systemd, а не `screen`: автозапуск после перезагрузки, перезапуск при падении,
логи в journald.

## Что можно доработать

- Перенос FSM в Redis
- Отмена и перенос записи клиентом
- Учёт длительности услуги при проверке занятости (сейчас бронируется один слот)
- Экспорт записей в календарь администратора
